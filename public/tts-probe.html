Reading aloud: what this phone can do

Three measurements. They decide whether the book can be read to you with the screen off, and whether it has to carry its own voice to do it. Run them on the phone you would actually listen on. Nothing here is saved or sent anywhere.

1 · The system voice, with the screen off

The cheap answer. Android has good voices built in and a web page can ask for them — but a page that stops talking when the screen locks is no use for listening. This speaks for about two minutes. Start it, lock the phone, and wait.

Not run yet.

2 · Ordinary audio, with the screen off

Two questions, not one. Does the sound survive the screen going off — and does the app's own code keep running while it does? The second decides whether speech can be made as you listen or has to be prepared first, and no amount of the first answers it. A soft pulse once a second for three minutes, with lock-screen controls. Start it, lock the phone for a minute or two, come back and press Stop.

Not run yet.

3 · A voice the book carries with it

Only needed if test 1 failed and test 2 passed. Downloads a small neural voice (Kokoro, about 90 MB the first time, then kept on the phone) and times it. Try the safe way first. It does the work on the processor, which every phone has and none gets wrong. The fast way hands it to the graphics chip, which is quicker where it works and produces noise where it does not — so if one of them screeches, that is the answer and the other one is the one to build on.

Not run yet.
